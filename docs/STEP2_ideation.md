## 과제 1. 롯데칠성음료 — AI 페르소나 기반 신제품 시장 검증

| ID | 아이디어 | 유형 | 구분 |
|---|---|---|---|
| 1-A | 페르소나 패널 설문 시뮬레이터 | 자동화 | 평범 |
| 1-B | 실제 조사 분포로 보정되는 페르소나 패널 (신뢰도 표시) | 오류 예방·판단 보조 | 차별화 |
| 1-C | 기출시 제품 역검증(Retro-validation) 하네스 | 의사결정 지원 | 차별화 |
| 1-D | 가상 컨조인트 + 다음 실험 컨셉 자동 선택 | 의사결정 지원 | 차별화 |
| 1-E | 가상 FGI 심층 인터뷰 → 거부 이유 클러스터 → 개선 컨셉 | 다중 정보원 | 중간 |

- **1-A 페르소나 패널 설문 시뮬레이터** — 인구통계로 페르소나 N명 생성 → 컨셉 제시 → 구매의향 5점 척도 집계 → 리포트. 가장 먼저 떠오르는 형태. 상용 합성 소비자 서비스(Synthetic Users 등)와 거의 동일 → 차별성 낮음.
- **1-B 보정형 페르소나 패널** — 핵심은 "시뮬레이션이 얼마나 믿을 만한가"를 에이전트가 스스로 측정·표시하는 것.
  - 작동: 공개된 실제 소비자 조사 결과(예: 식품소비행태조사의 음료 소비 문항 집계 — 미시데이터 공개 범위 [확인 필요])를 기준 분포로 두고, 같은 질문을 페르소나 패널에 던져 분포 차이를 측정 → 페르소나 구성 비율·프롬프트 조건을 조정해 차이를 줄임 → 세그먼트별 "신뢰 가능 / 불가" 표시
  - 검증: 실제 분포 대비 분포 거리(예: JS divergence), 응답 순위 상관. **보정 전후 비교가 그대로 성능 지표가 됨**
  - 유사: 학계의 'silicon sampling' 연구가 이 문제를 다룸 → 아이디어 자체는 새롭지 않으나, 운영 서비스에 신뢰도 게이트로 넣는 형태는 상대적으로 드묾 [가설]
- **1-C 기출시 제품 역검증 하네스** — 과거 출시된 음료(성공·단종 여부, 리뷰 평점 등 공개 정보)를 "출시 전 정보"만 주고 시뮬레이션 → 실제 결과와 맞는지 채점. 공식 과제의 "운영 프로세스 기획"에 정면 대응(이 서비스를 언제 믿어도 되는가). 라벨 데이터를 직접 구축해야 하는 노력이 큼.
- **1-D 가상 컨조인트 + 능동 실험 설계** — 컨조인트 분석(가격·당류·용량·맛·패키지 등 속성 조합을 보여주고 선택하게 해 속성별 선호도를 추정하는 기법)을 페르소나로 수행 → 속성별 효용 추정 → 불확실성이 가장 큰 조합을 다음 실험으로 자동 선택. 데이터사이언스 강점이 드러남. 단, 페르소나 응답 타당성 문제는 1-A와 동일하게 남음.
- **1-E 가상 FGI** — 정량 응답 후 "왜?"를 추가 질문 → 거부 이유를 군집화 → 개선 컨셉 생성 → 재시뮬레이션. 결국 생성·요약 중심이라 흔해지기 쉬움.

## 과제 2. 롯데웰푸드 — K-푸드 수출 유망국가 발굴

| ID | 아이디어 | 유형 | 구분 |
|---|---|---|---|
| 2-A | 국가 지표 가중 점수 + LLM 보고서 | 의사결정 지원 | 평범 |
| 2-B | 백테스트로 검증된 국가 순위 모델 + 근거 에이전트 | 의사결정 지원 | 차별화 |
| 2-C | 품목×국가 '기대 대비 공백' 탐지 | 이상(갭) 탐지 | 차별화 |
| 2-D | 비관세장벽·규제 적합성 사전 심사 | 오류 사전 예방 | 중간 |
| 2-E | 관심도 조기 신호 탐지 (검색·영상 트렌드 → 수출 선행성 검증) | 이상 탐지·다중 정보원 | 차별화 |

- **2-A 가중 점수 보고서** — 시장 규모·성장률·한국 식품 수입액 등에 사람이 정한 가중치를 주고 TOP 3 + LLM 보고서. 가중치 근거가 주관적이라 심사위원 질문에 약함.
- **2-B 백테스트 검증 순위 모델** — "2019년까지의 데이터만으로 2020~2024년 한국 과자·빙과류 수출이 가장 많이 성장한 나라를 맞힐 수 있었나?"를 검증해 가중치/모델을 학습(순위 학습). 에이전트는 데이터 수집(Comtrade·World Bank API 호출), 피처 생성, 순위 근거 설명, 민감도 분석(가중치를 흔들어도 TOP 3가 유지되는가)을 담당.
  - 검증: 백테스트 순위 지표(예: 상위 3개 적중 수, NDCG — 순위 정확도 지표)
  - 장점: "추천 근거"가 사람 의견이 아니라 과거 검증에 기반 → 심사 기준의 '결과 정확성'에 직접 대응
- **2-C 기대 대비 공백 탐지** — 국가별 식품 수입 구조(HS 6자리 품목 단위)에서 "경제 규모·거리·한류 지표로 예측한 한국산 수입 기대치" 대비 실제가 크게 낮은 품목×국가 조합 = 잠재 기회로 탐지(무역학의 중력모형 아이디어 활용). 롯데웰푸드 주력 품목군(제과·빙과 등, 공개 사업 정보) 중심.
- **2-D 규제 적합성 사전 심사** — 제품 원재료표와 후보국 첨가물·라벨·할랄 규정을 대조해 "수정 필요" 항목을 표시. 실무 가치는 크지만 규제 문서 수집·정확도 검증이 어렵고 단순 RAG(문서 검색 후 답변)로 보이기 쉬움.
- **2-E 관심도 조기 신호 탐지** — Google Trends, 유튜브·뉴스 언급량에서 K-푸드 관심이 급등하는 국가를 수출 통계보다 먼저 탐지. 핵심은 "검색 관심도가 실제 수출을 몇 개월 앞서는가"를 통계적으로 검증(시차 상관·그랜저 인과)한 뒤에만 신호로 채택하는 것. 데이터 수집 API 제한은 [확인 필요].

## 과제 3. 롯데홈쇼핑 — 프로모션 시뮬레이터

| ID | 아이디어 | 유형 | 구분 |
|---|---|---|---|
| 3-A | 매출 회귀 모델 + what-if 챗봇 | 의사결정 지원 | 평범 |
| 3-B | 증분 마진 기준 인과효과(업리프트) 시뮬레이터 | 의사결정 지원 | 차별화 |
| 3-C | 프로모션 기획안 사전 검증 (역마진·중복할인·재고·표시 문구) | 오류 사전 예방 | 차별화 |
| 3-D | 방송 중 실시간 실적 이탈 감지 → 추가 혜택 투입 제안 | 이상 탐지·후속 조치 | 차별화 |
| 3-E | 고객군별 반응 모형 기반 몬테카를로 시뮬레이션 (데이터 유입 시 자동 보정) | 의사결정 지원 | 중간 |
| 3-F | 프로모션 사후 성과 분석 자동 보고 | 자동화 | 평범 |

- **3-A** — 과거 매출 ~ 프로모션 변수 회귀 → 자연어 what-if. 프로모션 효과와 상품·시간대 효과가 섞여 있어 결과 왜곡 위험.
- **3-B 증분 마진 업리프트 시뮬레이터** — 상품·시간대·요일 등 교란 요인을 통제한 인과추정(Double ML 등: 교란 요인의 영향을 ML로 걸러내고 순수 효과만 추정하는 기법)으로 프로모션별 "추가로 생긴 매출"을 추정하고, 할인 비용·사은품 원가를 빼 **증분 마진** 기준으로 최적 조합을 추천.
  - 검증: 합성 데이터(정답 효과를 심어 둔 데이터)에서 효과 복원 오차, 공개 리테일 데이터(Dunnhumby 등)에서 홀드아웃 예측력
  - 위험: 실제 홈쇼핑 데이터가 없으면 "홈쇼핑 특화" 주장이 약함
- **3-C 기획안 사전 검증 에이전트** — MD가 쓴 프로모션 기획안(자연어·엑셀)을 구조화 → 마진 계산으로 역마진 탐지, 카드사 조건·중복할인 규칙 충돌, 사은품 재고 대비 예상 주문 초과, 과장 표현 문구(표시광고 관련 — 법률 판단은 참고용) 탐지 → 수정안 제시.
  - 검증: 결함을 의도적으로 주입한 기획안 세트로 탐지 정밀도·재현율 → **테스트셋을 직접 만들 수 있음**
  - 질문거리: 규칙 엔진만으로 충분하지 않은가? → 비정형 기획안 해석·규칙 밖 사례 추론이 LLM 역할
- **3-D 실시간 이탈 감지** — 방송 중 분 단위 주문 추이가 예측 범위를 벗어나면 원인 추정 + 추가 혜택 투입 여부 제안. 실무 임팩트는 크나 분 단위 데이터가 필수 → 합성 데이터 시연만 가능.
- **3-E 고객군 반응 몬테카를로** — 가격민감형·사은품선호형·할부선호형 등 고객군별 반응 파라미터를 두고 조합별 결과 분포(평균·위험)를 시뮬레이션, 실제 데이터가 들어오면 파라미터를 베이지안 방식으로 보정. 데이터 없을 때도 돌아가지만 파라미터 가정이 임의적이라는 비판에 취약.
- **3-F** — 사후 성과 보고 자동화. 단순 자동화·요약에 가까움.

## 과제 4. 롯데케미칼 — 첨단소재 수요예측 AI

| ID | 아이디어 | 유형 | 구분 |
|---|---|---|---|
| 4-A | 주문 이력 시계열 예측 + 대시보드 | 의사결정 지원 | 평범 |
| 4-B | 전방산업 분해 예측 (소재 수요 = Σ 전방산업 생산 × 사용 원단위) | 다중 정보원 | 차별화 |
| 4-C | 뉴스 이벤트 구조화 → 예측 보정 (보정 효과 백테스트) | 다중 정보원 | 차별화 |
| 4-D | 예측 이탈 감시 + 원인 자동 조사 + FCST 수정 제안 | 이상 탐지·후속 조치 | 차별화 |
| 4-E | 영업 담당자 예측 편향 보정·합의 보조 | 판단 보조 | 중간 |

- **4-A** — ARIMA·LightGBM 등으로 주문량 예측. 기본기 시연은 되나 AI 에이전트 요소가 거의 없음.
- **4-B 전방산업 분해 예측** — ABS·PC 수요를 자동차·가전·IT 기기 등 전방산업 생산 지표와 연결해 예측. 에이전트가 고객사→전방산업 매핑, 지표 수집, "전기차 생산 10% 증가 시" 같은 시나리오 계산을 담당. 공개 데이터로는 국가 단위 HS코드 수출입량을 대리 타깃으로 사용 [가설]. 원단위(제품 1대당 소재 사용량)는 공개 자료로 추정해야 해 오차 큼.
- **4-C 뉴스 이벤트 보정** — LLM이 뉴스(고객사 증설·감산, 리콜, 무역 규제, 원료 공장 사고)를 "이벤트 유형·대상·방향·크기" 구조로 추출 → 예측 모델의 보정 입력으로 사용 → **보정 전후 백테스트 오차 비교**로 LLM 기여를 정량 증명. LLM 필연성이 가장 분명. 과거 뉴스 아카이브 확보(GDELT 등 무료 소스 이용 가능 여부) [확인 필요].
- **4-D 예측 이탈 감시** — 실적이 예측 구간을 벗어나면 에이전트가 원인 후보(전방지표, 환율, 특정 국가 수입 급감, 관련 뉴스)를 자동 조사해 순위화하고 FCST 수정안 + 영업 알림 생성. 검증: 과거 이탈 시점을 재현해 원인 후보 적중 여부 확인(정답 라벨 구축 필요).
- **4-E 영업 예측 편향 보정** — 영업 담당자 입력 예측의 과거 편향(예: 상습적 낙관)을 학습해 통계 예측과 결합하고, 차이가 큰 품목에 확인 질문 생성. 영업 예측 이력이 내부 데이터라 합성 데이터 시연만 가능.

## 과제 5. 롯데호텔 — 고객 데이터 통합 및 맞춤 추천

| ID | 아이디어 | 유형 | 구분 |
|---|---|---|---|
| 5-A | 협업필터링 객실·패키지 추천 | 의사결정 지원 | 평범 |
| 5-B | 브랜드 간 동일 고객 식별(엔티티 해석) 에이전트 + 불확실 건 검토 큐 | 자동화·오류 예방 | 차별화 |
| 5-C | 지점별 이기종 스키마 자동 매핑·변환 코드 생성 | 병목 해소 | 차별화 |
| 5-D | 이력 적은 고객용 예약 맥락 기반 추천 + 업셀 타이밍 | 의사결정 지원 | 차별화 |
| 5-E | 브랜드 간 이탈 위험 예측 → 맞춤 오퍼 | 이상 탐지·후속 조치 | 중간 |

- **5-A** — 투숙 이력 기반 협업필터링. 호텔은 고객당 이력이 매우 적어(연 1~2회 [가설]) 협업필터링이 약하고, 흔함.
- **5-B 엔티티 해석 에이전트** — 브랜드·지점별 레코드(한글/영문 이름, 전화번호 형식, 이메일 오타, 회사명)를 규칙 → 임베딩 유사도 → LLM 판정 3단계로 병합하고, 확신이 낮은 건만 사람 검토 큐로 보냄.
  - 검증: 합성 데이터에 중복·변형을 의도적으로 심으면 **정답이 있으므로** 정밀도·재현율 측정 가능, 단계별 비용(LLM 호출 수) 대비 정확도 비교 가능
  - 공식 과제 1번째 항목(통합 체계 설계)에 정면 대응. 개인정보는 가명처리 전제
- **5-C 스키마 자동 매핑** — 지점마다 다른 예약 시스템 테이블 컬럼을 표준 스키마로 매핑하고 변환 코드를 생성·실행·검증. 검증: 매핑 정확도. 데이터 엔지니어링 비중이 높아 시연이 지루해질 위험.
- **5-D 맥락 기반 추천** — 고객 이력이 없어도 예약 맥락(동반 인원·아동 여부, 예약 리드타임, 체류 기간, 요일, 특별 요청)으로 목적(가족여행·출장·기념일)을 추정해 패키지·업그레이드 추천 + 추천 사유 + 체크인 전 메시지 시점 제안. Kaggle Hotel Booking Demand로 오프라인 평가(예: 특별 요청·객실 변경 예측) 가능하나 "패키지 구매" 정답은 없음.
- **5-E 브랜드 간 이탈** — 통합 프로필에서 재방문 감소 고객을 탐지해 맞춤 오퍼. 이탈 예측 경험과 맞으나 합성 데이터에서만 시연 가능.

## 과제 7. 한국후지필름 — 설문 기반 매출 확대 제안 AI 에이전트

| ID | 아이디어 | 유형 | 구분 |
|---|---|---|---|
| 7-A | 설문 자동 생성 + 결과 요약 보고서 | 자동화 | 평범 |
| 7-B | 정보량 기반 적응형 설문 설계 (문항 수 줄이고 예측력 유지) | 의사결정 지원 | 차별화 |
| 7-C | 설문 응답 → 고객별 매출 기회·이탈 점수 → 영업 다음 행동 큐 | 판단 보조 | 차별화 |
| 7-D | 설문 품질 사전 검증 (유도·이중 질문, 척도 불일치, 시계열 비교 불가 변경 탐지) | 오류 사전 예방 | 차별화 |
| 7-E | 개방형 응답 자동 코딩 + 회차 간 코드북 일관성 유지 | 자동화 | 중간 |

- **7-A** — 과거 자료 기반 문항 생성 + 응답 요약. 공식 과제 문장을 그대로 구현한 형태로, 사용자 요구사항 2(자동 요약 탈피)에 걸림.
- **7-B 적응형 설문** — 이전 회차 응답에서 정보량이 낮은 문항(모두 같은 답, 다른 문항과 중복)을 제거하고, 매출 결과 예측에 불확실성이 큰 영역 문항을 추가. 검증: 문항 수 대비 예측력·응답 완료율(시뮬레이션). 매출 연결 데이터가 없으면 "예측력" 정의가 어려움.
- **7-C 매출 기회 점수** — 응답 신호(불만, 사용량 증가, 교체 의향)를 고객별 기회·위험 점수로 바꿔 영업 담당자의 다음 행동 목록을 생성. 고객별 매출 데이터가 없으면 점수 타당성 검증 불가.
- **7-D 설문 품질 사전 검증** — 설문 방법론의 대표적 결함(유도 질문, 한 문항에 두 가지를 묻는 이중 질문, 척도 방향 불일치, 지난 회차와 비교를 깨는 문구 변경)을 탐지하고 수정안 제시.
  - 검증: 공개 설문 문항에 결함을 주입한 테스트셋 → 탐지 정밀도·재현율. **내부 데이터 없이 테스트셋 구성 가능**
  - 약점: 공식 과제의 핵심인 "매출 확대 제안"과의 연결이 간접적 → 단독으로는 과제 적합성 부족, 7-A·7-C의 앞단 모듈로 결합 필요
- **7-E 개방형 응답 코딩** — 자유 응답을 주제 코드로 분류하고 회차가 바뀌어도 코드 체계가 흔들리지 않게 유지. 검증: 사람 라벨과의 일치도(공개 리뷰 데이터로 대체 가능). 흔한 텍스트 분류에 가까움.

## 관찰 (STEP 3 전 메모)

1. **"정답을 직접 만들 수 있는가"가 개인 참가자에게 가장 큰 분기점.** 결함 주입 테스트셋(3-C, 7-D), 합성 중복 데이터(5-B), 과거 시점 백테스트(2-B, 4-C)는 내부 데이터 없이도 성능을 숫자로 보여줄 수 있음.
2. **페르소나·시뮬레이션 계열(1-A, 3-E, 1-D)은 "응답이 실제와 같다는 근거"가 없으면 심사 질문에 취약.** 1-B·1-C처럼 신뢰도 검증을 핵심 기능으로 넣어야 함.
3. **여러 과제에 걸친 공통 패턴**: "LLM이 비정형 정보를 구조화 → 통계/ML 모델이 계산 → 에이전트가 검증·설명". 4-C, 2-E, 3-C가 이 형태이며 사용자의 데이터사이언스 배경과 LLM 경험을 함께 보여주기 좋음.
4. 과제 6은 사용자 조건상 STEP 3에서 감점, 과제 7은 매출 연결 검증 수단이 약해 감점 가능성이 높음.
