1. AI 모델 설계
(1) 기본 예측 모델: 시차 변수, 계절성, 산업별 선행지표(자동차 생산, 산업생산지수, PMI, 환율 등)를 입력으로 하는 LightGBM과 통계 시계열 모델을 비교·앙상블합니다. 분위수 예측으로 예측 구간을 함께 산출합니다. 판매 이력이 짧은 제품은 유사 제품과 최종 수요 산업 지표를 이용해 보완합니다.
(2) 이벤트 추출 모델: LLM(OpenAI API)이 기사에서 이벤트를 JSON 스키마(유형·지역·산업·방향·강도·기간·근거 문장)로 추출합니다. 이벤트 유형은 감산·증설·리콜·관세/규제·물류 차질·수요 급변 6종으로 정의합니다.
(3) 보정 모델: 기본 예측의 잔차(오차)를 지역×산업×월 단위로 집계한 이벤트 피처로 학습합니다. 이벤트의 영향 크기는 과거 데이터에서 추정되며, 이벤트가 없으면 기본 예측을 그대로 사용합니다.
(4) 원인 조사: 예측 구간 이탈 시 선행지표 변화량, 지역·산업 분해 기여도, 관련 이벤트를 점수화해 원인 후보를 순위화합니다.

2. 활용 데이터
- 예선·사전 검증: 관세청 수출입무역통계의 ABS(HS 3903.30)·PC(HS 3907.40) 국가별 월간 수출입 물량을 공개 대리 지표로 사용합니다(롯데케미칼 실제 판매와 동일하지 않음을 명시). 선행지표는 국가별 자동차 생산·산업생산·PMI·환율, 뉴스는 GDELT 등 공개 뉴스 데이터베이스를 사용합니다.
- 본선: 현장 데이터(판매·주문 실적, 고객사 정보 등)를 예측 타깃으로 교체합니다. 입력 스키마를 '품목·고객(또는 산업)·지역·월·수량'으로 표준화해 타깃만 바꾸면 전체 파이프라인이 동작하도록 설계합니다.

3. AI 에이전트 개발 방식
- 구조: LLM이 계획 수립과 도구 호출을 담당하고, 계산은 검증된 Python 도구가 수행하는 함수 호출 기반 워크플로입니다. 도구는 데이터 조회기, 기본 예측기, 뉴스 수집기, 이벤트 추출기, 보정기, 이탈 감지기, 원인 조사기, 리포트 생성기로 구성합니다.
- 흐름: 요청 해석(품목·기간·지역) → 기본 예측 → 예측 시점 이전 뉴스 수집 → 이벤트 추출·중복 병합·근거 검증 → 보정 예측과 기여도 산출 → 이탈 감시·원인 조사 → 계획 수정안과 설명 리포트
- 화면: Streamlit으로 기본·보정 예측 비교 그래프, 이벤트 타임라인, 원인 조사 결과를 제공합니다.
- 1박 2일 개발 전략: 기본 예측과 이벤트 보정을 우선 완성하고, 원인 조사는 대표 사례 재현 수준으로 범위를 제한합니다.

4. 신뢰성·안정성 확보 방안
- 정량 검증: 매 시점 그때까지의 데이터와 뉴스만 쓰는 롤링 백테스트로 평가합니다. 비교 기준은 ⓐ작년 같은 달 ⓑ이벤트 없는 ML 모델 ⓒ키워드 빈도 피처 모델 ⓓLLM이 숫자를 직접 예측하는 방식입니다. 전체 기간과 이벤트 기간의 오차를 분리 보고하고, Diebold-Mariano 검정으로 개선이 우연인지 확인합니다.
- 미래 정보 누출 차단: 예측 시점 이후 기사는 사용하지 않습니다. LLM의 사전지식 누출을 점검하기 위해 회사명·날짜를 가린 기사로 추출 결과를 비교합니다.
- 환각 방지: 추출된 이벤트의 근거 문장이 원문에 실제로 있는지 자동 대조하고, 같은 사건을 다룬 여러 기사는 하나로 묶습니다. 근거가 약한 이벤트는 가중치를 낮춥니다.
- 이벤트 추출 품질: 기사 100건을 직접 라벨링해 추출 정확도(F1)를 측정합니다.
- 운영 안정성: 뉴스 수집이 불가능하면 기본 예측으로 자동 대체하고, 모든 보정 내역은 근거와 함께 기록해 담당자가 승인·거부할 수 있게 합니다.

5. 성능 평가 지표
- 예측: WAPE·MAPE, 예측 구간 포함률, 이벤트 기간 오차 감소율
- 이벤트 추출: 사람 라벨 대비 F1
- 원인 조사: 정답 원인이 상위 3개 후보에 포함되는 비율
- 안정성: 반복 실행 간 결과 변동폭, 응답 소요 시간

6. 본선 시연 구성
현장 데이터 적재 → 기본 예측 → 과거 큰 사건 시점 재현(기본 vs 보정 예측, 이벤트 타임라인) → 이탈 경보와 원인 조사 리포트 → 백테스트 성적표(오차 감소율·통계 검정 결과)를 순서대로 보여줍니다.
