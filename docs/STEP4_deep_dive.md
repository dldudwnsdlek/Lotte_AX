## A. 롯데웰푸드 — 검증형 수출 유망국 추천 에이전트 (2-B + 2-C)

### 1) 문제 상황과 사용 시나리오
- 배경 [보도]: 해외 매출 비중을 22.9%(2025)에서 2028년 35%로 높이는 것이 목표. 빼빼로는 약 57개국에 수출되며 2035년 1조 브랜드가 목표. 2026년에도 팬시푸드쇼·타이펙스 등에서 신규 국가 진출을 계속 추진 중.
- 시나리오: 해외사업팀 담당자가 입력한다. "빼빼로류(초콜릿 코팅 비스킷)의 다음 진출 후보 TOP 3를 근거와 함께. 이미 주력 수출국인 미국·필리핀은 제외."
  → 에이전트가 국가 순위, 순위의 과거 검증 성적, 국가별 근거 카드, 리스크, "가중치를 바꿔도 순위가 유지되는가"를 제시한다.
  → 후속 질문도 처리한다. "인도 공장 기준으로 다시", "시장 규모보다 성장률을 중시하면?"

### 2) 기존 해결 방식과 한계
| 기존 방식 | 한계 |
|---|---|
| 컨설팅 보고서, KOTRA·aT 자료 수작업 정리 [가설] | 갱신 주기가 길고 품목 단위 분석이 부족함 |
| 지표 가중 점수표 | 가중치가 주관적이고 "그 방식이 과거에 맞았는가"를 보여주지 못함 |
| 그룹 내 칠성 바이어 발굴 에이전트 [보도] | 대상국이 정해진 뒤 시장·바이어를 조사하는 도구로 보임 [가설]. 국가 선정 자체를 검증하지는 않음 |

### 3) 새로운 해결 방식
"**과거에 맞혔는지 검증된 순위 모델**"과 "**기대 대비 공백 탐지**"를 결합하고, 에이전트가 사용자 조건에 맞춰 재계산·근거 추적·반론 제시를 수행한다.
- 순위 모델: 시점 t의 국가별 지표로 t→t+3년 한국산 해당 품목 수입 증가를 예측하는 순위 학습 모델
- 공백 탐지: 경제 규모·거리·인구 등으로 계산한 "한국산 수입 기대치"보다 실제 수입이 크게 낮은 국가 = 잠재 기회 (무역학 중력모형 응용)

### 4) 에이전트 작업 순서
1. 요청 해석: 품목·제외 국가·제약(공급 거점, 최소 시장 규모)을 구조화
2. 데이터 도구 호출: 캐시된 무역 통계 조회, 부족 시 API 호출, 결측 시 수입국 측 보고치(미러 데이터)로 대체
3. 피처 계산: 시장 규모, 성장률, 한국산 점유율 추이, 1인당 소득, 도시화율, 거리, 한류 관심도(선택)
4. 순위 모델 실행 + 공백 점수 계산 → 두 신호를 결합한 후보 목록
5. 민감도 분석: 가중치·모델 변형 100회 → 국가별 TOP 3 잔존 확률
6. 근거 검증: 리포트의 모든 수치를 데이터 조회 결과와 대조(자가 검증)하고, 불일치하면 재작성
7. 반론 생성: 국가별 하락 리스크(환율, 경쟁국 점유율, 데이터 품질)를 명시
8. 리포트 출력 + 후속 질문(what-if) 대응

### 5) 기술과 데이터
| 구분 | 내용 |
|---|---|
| 데이터 | UN Comtrade(국가×HS품목×연도 수출입), CEPII Gravity DB(거리·공용어 등), World Bank WDI(GDP·인구·도시화), Google Trends(선택), 관세청·KATI(국내 통계 교차 확인) |
| 품목 코드 | 빼빼로류 HS 1905 하위 코드, 빙과 HS 2105 — **정확한 분류는 [확인 필요]** |
| 모델 | LightGBM 순위 학습(LambdaRank) 또는 로지스틱 회귀, 중력모형은 statsmodels 포아송 회귀(PPML) |
| 에이전트 | OpenAI 함수 호출(function calling: LLM이 정해진 도구를 골라 실행하게 하는 기능) 또는 LangGraph |
| 저장·UI | DuckDB 캐시, Streamlit |

### 6) 핵심 기능 3개
1. **백테스트 성적이 붙은 국가 순위** (예: "이 모델은 2016·2018·2020 시점 검증에서 상위 10개 중 평균 N개 적중")
2. **기대 대비 공백 탐지** — 순위 모델이 놓치는 "아직 작지만 구조적으로 커질 수 있는 시장"을 보완
3. **조건 재계산 + 근거 추적 리포트** — 모든 문장이 데이터 출처·수치와 연결됨

### 7) MVP 범위
- 품목 2개(비스킷류, 빙과), 국가 약 100개, 2010~2024년 연간 데이터
- 백테스트 시점 3개, Streamlit 화면 1개(질문 → 순위·근거·민감도)
- 제외: 실시간 데이터 갱신, 규제 심사, 공급 거점 계산(2-F, 확장 과제)

### 8) 테스트 데이터 구성
- 기준 시점 t ∈ {2016, 2018, 2020}: 피처는 t년까지만 사용 (미래 정보 누출 금지)
- 정답: t→t+3년 한국산 해당 품목 수입액 증가(로그 차분) 순위
- 소규모 노이즈 제거: 기준 시점 수입액이 일정 금액 미만인 국가는 별도 처리

### 9) 성능 지표와 비교 기준
| 지표 | 설명 |
|---|---|
| Hit@3, Hit@10 | 예측 상위 3·10개 중 실제 상위권에 든 국가 수 |

| Spearman 순위 상관 | 전체 순위 일치도 |

비교 기준(베이스라인): ① 최근 3년 성장률 단순 외삽 ② 시장 규모순 ③ 사람이 정한 가중 점수표

- **타임머신 화면**: 2018년 시점으로 돌려 예측 → 실제 2021년 결과와 나란히 비교
- 가중치 슬라이더로 순위 안정성 변화 확인

### 11) 예상 실패 원인과 대처
| 실패 원인 | 대처 |
|---|---|

## B. 롯데케미칼 — 이벤트 인지형 수요예측 에이전트 (4-C + 4-D)

### 1) 문제 상황과 사용 시나리오
- 배경 [보도]: 첨단소재가 매출의 26.7%이고 그중 ABS 34.8%, PC 39.0%. 적용처는 가전·IT·의료기기·자동차. 신규 컴파운드 공장(율촌, 50만 톤)이 가동 중. 수요예측 AI 적용은 공개 자료에서 확인되지 않음.
- 시나리오: 수요계획 담당자가 다음 분기 ABS·PC 판매계획을 세운다. 뉴스에 "주요 가전사 해외 공장 감산", "EV 판매 둔화"가 보도된다.
  → 에이전트가 관련 이벤트를 구조화해 예측을 보정하고, 보정 근거를 보여준다.
  → 지난달 실적이 예측 범위를 벗어나면 원인 후보를 조사해 순위로 보고하고 수정안을 낸다.

### 2) 기존 해결 방식과 한계
| 기존 방식 | 한계 |
|---|---|
| 영업 담당자 감 + 과거 실적 기반 계획 [가설] | 사람마다 편향이 다르고 근거 기록이 없음 |
| 통계 시계열 모델 | 감산·리콜·규제 같은 구조 변화를 반영하지 못함 |
| 아이멤버 화학 시장 전망 에이전트 [보도] | 거시 전망 리포트로 보이며, 예측 수치에 정량 반영되는지는 불명 [가설] |

### 3) 새로운 해결 방식
- **LLM은 뉴스를 "구조화된 이벤트"로 바꾸는 역할만** 하고, 이벤트가 수요에 미치는 **크기는 통계 모델이 과거 데이터로 학습**한다.
- LLM이 숫자를 직접 예측하지 않으므로 환각(그럴듯한 거짓 생성) 위험을 줄이고, 보정 효과를 백테스트로 측정할 수 있다.

### 4) 에이전트 작업 순서
1. 기본 예측: 국가·품목별 월간 수요(대리 타깃)를 시계열 ML로 예측하고 예측 구간을 산출
2. 뉴스 수집: 예측 시점 이전 기사만, 전방산업 키워드(가전·자동차·IT 등) 기준
3. 이벤트 추출: LLM이 JSON 스키마로 출력 {유형, 국가, 산업, 방향(+/-), 강도(1~3), 예상 기간, 근거 문장}
4. 중복 제거·검증: 같은 사건의 여러 기사를 묶고, 근거 문장이 원문에 실제로 있는지 확인
5. 이벤트 피처화: 국가×산업×월 단위로 집계
6. 보정: 기본 예측의 잔차(오차)를 이벤트 피처로 학습한 보정 모델 적용
7. 이탈 감시: 실적이 예측 구간 밖이면 원인 조사 시작 → 선행지표 변화, 국가별 분해, 관련 이벤트를 조사해 원인 후보 순위화
8. 계획 수정안 + 설명 생성

| 구분 | 내용 |

| 뉴스 | GDELT(전 세계 뉴스 이벤트 DB, 무료, 2015년~), 국내 뉴스 검색 API(과거 기사 범위 [확인 필요]) |
| 모델 | LightGBM 또는 통계 모델, 사전학습 시계열 모델(예: Chronos 소형, CPU 가능) 비교 |
| 에이전트 | OpenAI 구조화 출력(JSON 스키마 강제) + 함수 호출, Streamlit |

### 6) 핵심 기능 3개
1. **뉴스 → 구조화 이벤트 추출** (근거 문장 검증 포함)
2. **이벤트 기반 예측 보정 + 보정 기여도 표시** ("이번 달 예측 −6% 중 −4%p는 ○○ 감산 이벤트")
3. **예측 이탈 시 원인 자동 조사 + 수정안**

### 7) MVP 범위

- 이벤트 유형 6종(감산·증설·리콜·규제/관세·물류 차질·수요 급변)
- 원인 조사는 과거 이탈 사례 재현 중심

### 8) 테스트 데이터 구성
- 롤링 백테스트: 매월 그 시점까지의 데이터와 뉴스만 사용해 1~3개월 뒤 예측
- 이벤트 추출 정확도: 기사 100건을 직접 라벨링해 LLM 추출 결과와 비교
- 원인 조사: 큰 이탈 사례(코로나 초기, 차량용 반도체 부족, 중국 봉쇄 등 — 대리 타깃에서 실제 이탈이 있는지 [확인 필요])에 정답 원인 라벨 부여

### 9) 성능 지표와 비교 기준
| 지표 | 설명 |

| 이벤트 추출 F1 | 사람 라벨 대비 정확도 |
| 원인 조사 Top-3 적중률 | 정답 원인이 상위 3개 후보에 드는 비율 |

비교 기준: ① 계절성 단순 예측(작년 같은 달) ② 이벤트 없는 ML 모델 ③ LLM에게 숫자를 직접 예측시키는 방식

### 10) 본선 시연 결과물
- 과거 위기 시점 재현: 기본 예측 vs 보정 예측 그래프와 이벤트 타임라인
- 이탈 경보 → 원인 조사 리포트 생성 과정 실시간 시연
- 백테스트 성적표 (오차 감소율, 통계 검정 결과)

### 11) 예상 실패 원인과 대처
| 실패 원인 | 대처 |
|---|---|
| **LLM 사전지식 누출**: LLM이 이미 미래 결과를 알고 있어 백테스트가 부풀려질 위험 | LLM은 주어진 기사에서 사실만 추출하고 영향 크기는 통계 모델이 학습. 회사명을 가린 기사로 추출 결과 비교(누출 점검) |
| 과거 뉴스 아카이브 확보 실패 | 수작업 이벤트 캘린더(50~100건)로 대체하고, LLM 추출은 최근 기사로만 정확도 검증 |
| 보정 효과가 미미함 | 이벤트 기간 한정 성과를 분리 보고, 효과가 없으면 정직하게 보고 |
| 월간 데이터 길이가 짧음(약 120개 시점) | 단순 모델, 국가 간 데이터 결합(패널) |
| 대리 타깃과 실제 판매의 괴리 | 설계를 "타깃 교체 가능" 구조로 만들고, 대회 데이터 제공 시 교체 |

### 12) 경쟁 아이디어와의 차별성
- 일반적인 "시계열 예측 + 대시보드"와 달리 **LLM 기여도를 숫자로 증명**
- 시장 전망 리포트형(아이멤버 화학 에이전트 [보도])과 달리 **예측 수치에 직접 반영되고 오차로 평가**됨
- 사용자 배경(예측 모델링 + LLM)이 가장 직접적으로 드러남
- **약점**: 공개 대리 타깃이라 "롯데케미칼 고객사 단위"까지는 시연할 수 없음

## C. 롯데호텔 — 다국어 고객 식별 + 맥락 추천 에이전트 (5-B + 5-D)

### 1) 문제 상황과 사용 시나리오
- 배경 [보도]: 회원 약 470만 명을 단일 리워즈로 통합 완료, 외국인 투숙객 +13.1%, 2026.9 멤버십 등급 개편
- 시나리오: 중국 고객이 OTA로 L7 명동을 예약한다(이름 "WANG XIAOMING", 이메일 마스킹). 이 고객은 2년 전 롯데호텔 부산에 직접 예약했던 회원 "王小明"과 같은 사람일 수 있다.
  → 에이전트가 동일인 가능성을 근거와 함께 판정한다.
  → 확실하면 회원 프로필과 연결해 등급 혜택·선호(고층, 금연)를 반영하고, 예약 맥락(2인, 3박, 주말)으로 패키지를 추천한다.
  → 애매하면 프론트 직원 확인 요청 큐로 보낸다.

### 2) 기존 해결 방식과 한계
| 기존 방식 | 한계 |
|---|---|
| 회원 ID 기반 통합 [보도] | 비회원·OTA·여행사 예약은 회원 ID가 없음 [가설] |
| 정확 일치 규칙(이름+전화) | 로마자 표기 차이(이/Lee/Yi/Rhee), 한자·병음·가타카나, 전화 형식, 오타에 취약 |
| 협업필터링 추천 | 호텔 고객은 이력이 적어 효과가 약함 [가설] |

### 3) 새로운 해결 방식
**규칙 → 확률 매칭 → LLM 판정 → 사람 검토**의 단계형 식별. 비용이 싼 단계에서 대부분 처리하고 애매한 건만 LLM, 그래도 애매하면 사람에게 넘긴다. 통합된 프로필과 예약 맥락으로 추천한다.

### 4) 에이전트 작업 순서
1. 신규 예약 레코드 수신
2. 정규화: 전화(국제 표준 형식), 이름 로마자·한자 변환, 이메일 정규화
3. 후보 생성(blocking: 비교 대상을 줄이는 사전 필터): 생년월일, 전화 끝자리, 이름 발음 키
4. 확률 매칭 점수 계산 (Fellegi-Sunter 모델 또는 LightGBM)
5. 점수가 애매한 구간만 LLM 판정 + 판정 근거 작성 (원본 개인정보는 가명 토큰으로 전달)
6. 여전히 애매하면 사람 검토 큐 (잘못된 병합은 비용이 크므로 정밀도 우선)
7. 통합 프로필 → 여행 목적 추정(가족·출장·기념일) → 패키지·객실 추천 + 안내 메시지 초안

### 5) 기술과 데이터
| 구분 | 내용 |
|---|---|
| 식별 데이터 | **정답이 있는 합성 고객 데이터** — Faker(가짜 개인정보 생성 라이브러리)로 한·중·일·영 고객 생성 + 변형 주입(로마자 표기 변이, 병음/헵번식, 오타, 마스킹, 전화 형식, 결혼 후 성 변경 등) |
| 추천 데이터 | Kaggle Hotel Booking Demand(약 12만 건 예약, 포르투갈 호텔 2곳) — 예약 맥락으로 식사 플랜·특별 요청·객실 변경 예측을 패키지 추천의 대리 과제로 사용 |
| 도구 | Splink(오픈소스 확률적 레코드 매칭), pypinyin 등 표기 변환, OpenAI API, Streamlit |

### 6) 핵심 기능 3개
1. **다국어 표기를 견디는 단계형 동일인 식별** (LLM 호출 최소화)
2. **판정 근거 + 사람 검토 큐** (잘못된 병합 방지)
3. **통합 프로필 기반 맥락 추천 + 메시지 초안**

### 7) MVP 범위
- 합성 레코드 1만~5만 건, 브랜드 4개 출처(시그니엘·롯데호텔·L7·OTA를 흉내 낸 서로 다른 스키마)
- 식별 파이프라인 + 검토 큐 화면 + 추천 1종
- 제외: 실시간 PMS(호텔 운영 시스템) 연동, 대규모 분산 처리

### 8) 테스트 데이터 구성
- 합성 생성기의 변형 유형·비율을 파라미터로 공개(재현 가능)
- 난이도별 세트: 쉬움(오타), 중간(로마자 변이), 어려움(한자↔병음 + 연락처 불일치)
- 추천: Kaggle 데이터를 시간 순으로 나눠 학습·평가

### 9) 성능 지표와 비교 기준
| 지표 | 설명 |
|---|---|
| 쌍 단위 Precision / Recall / F1 | 같은 사람 판정의 정밀도·재현율 |
| B-cubed F1 | 고객 묶음 단위 정확도 |
| LLM 호출 비율·비용 | 전체 중 LLM까지 간 건의 비율 |
| 검토 큐 비율 | 사람 확인이 필요한 비율 (업무 부담) |
| 추천 HitRate@k, NDCG | 오프라인 추천 정확도 |

비교 기준: ① 정확 일치 규칙 ② Splink 단독 ③ 모든 쌍을 LLM으로 판정(비용 비교) / 추천: 인기 기반

### 10) 본선 시연 결과물
- 합성 데이터 투입 → 통합 전/후 고객 수, 난이도별 정확도 대시보드
- 애매한 사례에서 LLM 판정 근거를 보여주는 화면
- 동일 고객의 통합 전/후 추천 변화 비교

### 11) 예상 실패 원인과 대처
| 실패 원인 | 대처 |
|---|---|
| "합성 데이터라 현실과 다르다"는 비판 | 변형 규칙을 실제 표기 규범(외래어·로마자 표기법)에 근거해 설계하고, 파라미터를 공개해 민감도 분석 |
| LLM 과병합(다른 사람을 같은 사람으로) | 정밀도 우선 임계값, 사람 검토 큐 |
| 개인정보 처리 문제 | 가명 토큰화, 최소 정보 전달, 국내 처리 옵션(아이멤버는 국내 서버 처리 [보도]) 언급 |
| 추천 평가가 약함 | 추천은 보조 기능으로 두고 식별을 핵심 성과로 제시 |

### 12) 경쟁 아이디어와의 차별성
- 대부분 참가자는 추천 알고리즘에 집중할 것으로 예상됨 [가설] → 본 안은 과제 첫 줄(통합 체계)을 **측정 가능한 형태로** 해결
- 엔티티 해석 자체는 성숙한 분야(Splink, 상용 CDP)라 **기술적 독창성은 중간**. 차별점은 다국어 표기 + 호텔 맥락 + 비용 최적화된 단계 구조

## D. 롯데칠성음료 — 신뢰도 보정 페르소나 패널 (1-B)

### 1) 문제 상황과 사용 시나리오
- 배경 [보도]: 그룹사 롯데웰푸드는 AI 소비자 응답과 실제 소비자 응답을 **50:50 고정 비중**으로 섞어 컨셉 조사에 활용 중. 칠성은 제품 개발에 소비자 선호 분석 AI를 쓰지 않는다고 밝힘.
- 시나리오: 브랜드팀이 저당 탄산음료 컨셉 3종을 비교한다.
  → 페르소나 패널 1,000명이 응답하고, 결과와 함께 **세그먼트별 신뢰도 지도**가 나온다. 예: "20~30대 여성: AI 응답이 실제와 잘 맞음 / 50대 이상 남성: 맞지 않음"
  → 에이전트가 "실제 조사 표본 300명 중 220명을 신뢰도가 낮은 세그먼트에 배정하라"고 추천한다.
- **비즈니스 가치**: AI 응답을 무조건 믿거나 버리는 대신, **실제 조사 예산을 AI가 약한 곳에 집중**한다.

### 2) 기존 해결 방식과 한계
| 기존 방식 | 한계 |
|---|---|
| 전수 실제 조사(설문·FGI) | 시간·비용 |
| AI 응답 단독 사용 | 실제와 다를 때 알 방법이 없음 |
| AI·실제 고정 비중 혼합 [보도] | 세그먼트·문항마다 AI 정확도가 다른데 같은 비중을 적용 |

### 3) 새로운 해결 방식
기준 조사(실제 응답이 있는 공개 조사)에서 **세그먼트 × 문항 유형별로 AI 응답이 실제와 얼마나 맞는지 측정** → 신뢰도 지도 작성 → 신규 컨셉 조사에서 ① 혼합 비중을 신뢰도에 따라 다르게 적용하고 ② 실제 조사 표본을 신뢰도가 낮은 세그먼트에 배정한다.

### 4) 에이전트 작업 순서
1. 인구통계 분포에 맞춘 페르소나 생성(층화 표본)
2. 기준 조사 문항을 페르소나에게 질문
3. 실제 분포와 비교 → 세그먼트·문항 유형별 오차 계산
4. 보정: 프롬프트 조건 보강, 사후 가중, 분포 재보정
5. 따로 떼어 둔 문항(홀드아웃)으로 보정 효과 검증
6. 신규 컨셉 조사 실행 → 결과 + 신뢰도 지도 + 실제 표본 배정안
7. 실제 응답이 들어오면 신뢰도 지도 갱신(운영 프로세스)

### 5) 기술과 데이터
| 구분 | 내용 |
|---|---|
| 기준 데이터 | 실제 응답 미시데이터(개인 단위 응답)가 있는 공개 조사가 필요. 후보: 한국농촌경제연구원 식품소비행태조사 원자료(공개·신청 절차 [확인 필요]), 해외 공개 설문(대체용) |
| 모델 | OpenAI 등 LLM(저가 모델로 대량 응답), 통계 보정(raking: 집단 비율을 맞추는 가중법, 분위수 매핑) |
| UI | Streamlit |

### 6) 핵심 기능 3개
1. **세그먼트별 AI 응답 신뢰도 지도**
2. **신뢰도 기반 혼합 추정** (고정 50:50 대비)
3. **실제 조사 표본 배정 추천** (같은 예산으로 오차 최소화)

### 7) MVP 범위
- 기준 조사 1개, 세그먼트 8~12개(성별×연령대), 문항 유형 3종(선호·구매 빈도·가격 수용도)
- 컨셉 조사 데모 1건

### 8) 테스트 데이터 구성 (핵심 실험)
- 실제 조사 전체 응답(N명)의 결과를 "참값"으로 둔다
- 예산이 n명(예: N의 10%)뿐이라고 가정하고 세 추정 방식을 비교한다
  - ⓐ 실제 n명만 사용
  - ⓑ 실제 n명 + AI 응답 50:50 고정 혼합
  - ⓒ 실제 n명(신뢰도 기반 배정) + AI 응답 신뢰도 기반 혼합
- 각 방식의 참값 대비 오차를 측정. 무작위 추출을 수백 번 반복해 분포로 비교

### 9) 성능 지표와 비교 기준
| 지표 | 설명 |
|---|---|
| 세그먼트별 Jensen-Shannon 거리 | AI 응답 분포와 실제 분포의 차이 (0이면 동일) |
| 추정 오차(MAE) | 위 실험에서 참값 대비 오차 |
| 동일 오차 달성에 필요한 실제 표본 수 | "실제 조사 비용 X% 절감"으로 환산 |
| 컨셉 선호 순위 일치도 | 순위 상관 |

비교 기준: ⓐ 실제만, ⓑ 고정 혼합(그룹 내 현행 방식으로 보도된 형태), 비보정 페르소나

### 10) 본선 시연 결과물
- 컨셉 입력 → 수 분 내 결과 + 신뢰도 히트맵 + 표본 배정안
- 백테스트 결과: "같은 예산으로 오차 ○% 감소" 그래프

### 11) 예상 실패 원인과 대처
| 실패 원인 | 대처 |
|---|---|
| **음료 관련 실제 응답 미시데이터 확보 실패 (최대 위험)** | 예선 전에 확보 가능 여부부터 확인. 실패 시 식품 일반 소비 문항으로 범위 축소 |
| 모든 세그먼트에서 AI 정확도가 낮음 | 그 자체를 결과로 제시("AI를 쓰면 안 되는 곳을 알려준다") — 운영 프로세스 가치 |
| LLM 응답 동질화(모두 비슷한 답) | 다양성 프롬프트, 복수 모델, temperature 조정 |
| 비용(1,000명 × 수십 문항) | 저가 모델, 배치 API, 캐시 |

### 12) 경쟁 아이디어와의 차별성
- 이 과제에서는 "페르소나 생성 → 설문 → 리포트"형 제출이 많을 것으로 예상됨 [가설] → 본 안은 **"언제 믿을 수 있는가"를 측정하는 운영 계층**
- 학계 연구(silicon sampling)와 상용 합성 소비자 서비스는 존재 → 차별점은 **실제 조사 예산 배정까지 연결한 하이브리드 운영 방식**
- **약점**: 데이터 확보 위험이 5개 후보 중 가장 큼

## E. 롯데홈쇼핑 — 사전 검증 내장 프로모션 시뮬레이터 (3-B + 3-C)

### 1) 문제 상황과 사용 시나리오
- 배경 [보도]: 2018년부터 AI 편성 시스템으로 상품별 시간대 매출을 예측. ChatGPT 앱 등에서 할인 혜택을 안내함.
- 시나리오: MD가 "다음 주 화요일 21시 공기청정기 방송"의 프로모션안 3개(카드 7% 할인 / 필터 사은품 / 무이자 12개월)를 엑셀로 올린다.
  → ① 사전 검증: 역마진, 중복 할인 충돌, 사은품 재고 부족, 채널별 안내 문구 불일치 탐지
  → ② 시뮬레이션: 조합별 증분 매출·**증분 마진**과 불확실성 구간
  → ③ 최적안 추천 + 근거 ("매출 1위안과 마진 1위안이 다르다")

### 2) 기존 해결 방식과 한계
| 기존 방식 | 한계 |
|---|---|
| MD 경험 + 과거 유사 방송 참고 [가설] | 조합이 많고 효과가 상품·시간대 효과와 섞임 |
| AI 편성의 매출 예측 [보도] | 상품·시간 배치 중심. 프로모션 조건별 효과 분리가 되는지는 불명 [가설] |
| 사후 성과 분석 | 이미 비용이 발생한 뒤에야 알게 됨 |

### 3) 새로운 해결 방식
기존 매출 예측을 기본값으로 받는다고 가정하고 [가설] 그 위에 **프로모션 효과 계층**을 얹는다. 효과는 교란 요인(상품·시간대·요일)을 통제한 인과추정으로 계산하고, 매출이 아니라 **증분 마진** 기준으로 최적화한다. 앞단에 **기획안 사전 검증**을 둔다.

### 4) 에이전트 작업 순서
1. 기획안(엑셀·자연어) 파싱 → 구조화(상품, 시간, 조건, 비용, 재고)
2. 사전 검증: 규칙 검사(마진, 중복, 재고) + LLM 문구 검사(채널별 안내 문구 정합성)
3. 기본 매출 예측 조회(기존 시스템 대체 모델)
4. 프로모션 효과 모델로 조합별 증분 효과·불확실성 계산
5. 제약(예산, 마진 하한, 재고) 하에서 최적 조합 탐색
6. 결과 설명 + what-if 질의 대응

### 5) 기술과 데이터
| 구분 | 내용 |
|---|---|
| 효과 모델 학습 | 공개 리테일 데이터(Dunnhumby The Complete Journey: 쿠폰·캠페인 포함 가구 구매 데이터) + **정답 효과를 심어 둔 합성 홈쇼핑 데이터** |
| 인과추정 | EconML(마이크로소프트 오픈소스): Double ML, 메타러너 |
| 최적화 | scipy / OR-Tools |
| 검증 모듈 | 규칙 5종 + LLM 문구 비교 |
| UI | Streamlit |

### 6) 핵심 기능 3개
1. **기획안 사전 검증** (역마진·중복·재고·채널 문구)
2. **증분 마진 기준 조합 시뮬레이션** (불확실성 구간 포함)
3. **제약 하 최적안 + 설명**

### 7) MVP 범위
- 프로모션 유형 3종(카드 할인, 사은품, 무이자), 상품군 3개, 검증 규칙 5종
- 합성 데이터 + 공개 데이터 홀드아웃 검증

### 8) 테스트 데이터 구성
- 합성 데이터: 상품·시간대가 프로모션 배정에 영향을 주도록(교란) 설계하고 정답 효과를 심음
- 공개 데이터: 캠페인 기간 데이터를 시간 순으로 분할
- 검증 모듈: 결함 주입 기획안 100건(유형별)

### 9) 성능 지표와 비교 기준
| 지표 | 설명 |
|---|---|
| 효과 추정 오차 | 심어 둔 정답 효과 대비 오차 |
| 최적안 후회값(regret) | 선택한 안의 마진과 진짜 최적안 마진의 차이 |
| 홀드아웃 예측 오차 | 공개 데이터 |
| 검증 모듈 Precision / Recall | 결함 탐지 정확도 |

비교 기준: 교란을 통제하지 않은 단순 회귀(효과가 부풀려지는 것을 보여줌), 매출 최대화 기준 최적안

### 10) 본선 시연 결과물
- 기획안 업로드 → 결함 3건 탐지 → 수정 → 조합 12개 시뮬레이션 → 매출 1위 vs 마진 1위 비교 화면

### 11) 예상 실패 원인과 대처
| 실패 원인 | 대처 |
|---|---|
| "정답을 심어 놓고 맞힌 것"이라는 순환 논리 비판 | 공개 실제 데이터 홀드아웃을 병행, 대회 데이터 제공 시 즉시 교체되는 구조 |
| 홈쇼핑 특화성 부족 | 방송 시간대·쇼호스트·할부 등 홈쇼핑 변수를 스키마에 반영, 데이터 교체 시 활성화 |
| 두 모듈로 범위가 과다 | 검증 규칙을 5종으로 제한, 최적화는 전수 탐색(조합 수가 작음) |

### 12) 경쟁 아이디어와의 차별성
- 일반적인 "매출 예측 + what-if"와 달리 **증분 마진**과 **사전 검증**
- **대회가 실제 판매 데이터를 제공하면 5개 후보 중 가치가 가장 크게 오름** / 제공하지 않으면 가장 약해짐
