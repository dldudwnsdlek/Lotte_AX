## 0. FAQ가 바꾼 판단

| 변화 | 영향 |
|---|---|
| **예선에서 고른 과제가 본선에서 "구체화"된다** | 과제 선택이 본선까지 이어짐. 구체화된 과제가 무엇이든 대응할 수 있는 **범용적인 핵심 구조**가 중요 |
| **본선에 현장(실제) 데이터가 주어진다** | "내부 데이터 없음" 감점이 본선 기준으로는 크게 완화됨 → 홈쇼핑(E)의 데이터 약점이 줄어듦. 공개 대리 데이터(케미칼 HS 수출량 등)는 **예선 증명용**으로 역할이 바뀜 |
| **데이터·세부 과제를 당일에야 안다** | 1박 2일 안에 "데이터 파악 → 적용 → 시연"을 해야 함 → 미리 만든 공개 데이터 전용 파이프라인보다 **새 데이터를 빠르게 꽂을 수 있는 도구형 설계**가 유리. 복잡한 다중 모듈 설계는 불리 |
| 예선은 여전히 데이터 없이 평가됨 | 예선 기획서·포트폴리오에 **공개 데이터로 만든 작은 실증 결과**를 넣을 수 있는 후보가 예선 통과에 유리 [가설] |

### 후보 재평가
- **D 칠성**: 현장 데이터(예: 과거 컨셉 조사 결과, 소비자 조사)가 주어지면, 그것이 곧 보정 엔진이 필요로 하는 "실제 응답"이 됨 → **오히려 강화**. 공개 데이터(KREI)로 예선 실증도 가능
- **B 케미칼**: 실제 수요 데이터가 주어지면 대리 타깃 문제가 해소됨. 하지만 뉴스 이벤트 모듈은 **본선 인터넷 사용 여부에 좌우**되고, 미리 수집한 뉴스가 현장 데이터의 기간·고객과 맞지 않을 수 있음 → 핵심 모듈의 불확실성 증가
- **E 홈쇼핑**: 본선 데이터 문제는 완화되어 **조건부 부활**. 단, AI 에이전트 필연성 약점(11/20)과 1박 2일 안에 관측 데이터로 인과추정을 하는 난도는 그대로. 예선 단계에서 보여줄 실증이 합성 데이터뿐
- **A 웰푸드**: 공개 데이터 실증이 가장 쉬움. 에이전트 필연성 약점은 재설계로 보완해야 함
- **C 호텔**: 현장 데이터로 개인정보 문제는 일부 해소될 수 있으나 "더 단순한 대안" 문제와 과제 2번째 줄(추천) 약점은 그대로 → 탈락 유지

## 2. 1순위 — D. 롯데칠성음료: 신뢰도 보정 AI 소비자 패널

### 선정 이유
1. **LLM이 핵심 기능 그 자체**(AI 소비자 = LLM)여서 "굳이 AI인가?" 질문에 가장 강함
2. **그룹 내 실제 운영 방식의 빈틈을 겨냥**: 롯데웰푸드는 AI·실제 응답을 50:50 고정 비중으로 혼합 중 [보도] → "세그먼트·문항별로 다르게 믿어야 한다"는 개선 제안은 현업 적용 논리가 분명
3. **예선 실증 가능**: KREI 식품소비행태조사 원자료(공개 다운로드 확인)에 음료 선호 순위·제로 음료 섭취 빈도·이유 문항이 있음 → 기획서에 실제 수치를 넣을 수 있음
4. **본선 현장 데이터와 궁합**: 어떤 소비자 데이터가 주어져도 "보정 기준"으로 꽂을 수 있는 구조
5. **결과가 비즈니스 수치로 번역됨**: "같은 실제 조사 예산으로 오차 ○% 감소" 또는 "같은 정확도에 조사 비용 ○% 절감"

### 가장 중요한 차별화 요소
"AI 소비자 시뮬레이션"이 아니라 **"AI 소비자 응답의 신뢰도 지도 + 실제 조사 표본 배정"**. 많은 참가자가 낼 것으로 예상되는 "페르소나 생성 → 설문 → 리포트"형과 달리, **AI를 쓰면 안 되는 곳까지 알려주는 운영 장치**

### 개발 난이도: **중**
- 페르소나 생성·응답 수집은 쉬움 / 보정·혼합 추정·표본 배정은 통계 이해가 필요하지만 사용자 배경(데이터사이언스)에 맞음

### 필요한 기술 스택
| 영역 | 도구 |
|---|---|
| LLM | OpenAI API (구조화 출력·배치), 응답 다양성 확보를 위한 복수 모델 비교(선택) |
| 데이터 | pandas, KREI 원자료(Excel/SPSS → pyreadstat) |
| 통계 | 분포 거리(Jensen-Shannon), raking(집단 비율 맞춤 가중), 혼합 추정, 층화 표본 배정(네이만 배분: 분산이 큰 집단에 표본을 더 주는 방식) |
| 에이전트 | 함수 호출 기반 워크플로(조사 설계 → 실행 → 측정 → 추천) |
| UI | Streamlit (신뢰도 히트맵, 컨셉 비교) |

### 최소 개발 범위 (MVP)
1. 인구통계 분포에 맞춘 AI 소비자 패널 생성 (성별×연령 8~12개 세그먼트)
2. KREI 문항(A15 음료 선호, A19 제로 음료 빈도, A19-1 이유)으로 **세그먼트별 신뢰도 지도** 산출
3. 신규 컨셉 1건(예: 제로 탄산 신제품) 시뮬레이션 + 신뢰도 표시 + **실제 조사 표본 배정안**
4. 백테스트: "실제 n명만 / 50:50 고정 혼합 / 신뢰도 기반 혼합" 오차 비교 그래프

### 예상되는 최대 위험 요소
- **신뢰도 전이 문제**: 일반 소비 문항에서 잰 신뢰도가 신제품 컨셉 평가 문항에도 통하는지 보장되지 않음 → 문항 유형 간 홀드아웃으로 전이 정도를 수치화하고 한계를 명시
- (부차) 과제 1은 진입장벽이 낮아 참가자가 몰릴 가능성 [가설] → 차별화 메시지를 기획서 첫 장에 배치
- (부차) 실험 결과 AI 응답 혼합의 이득이 작게 나올 가능성 → "AI 사용 금지 구간을 찾아준다"는 가치로 전환

### 다른 후보보다 유리한 점
- B보다: 사전 준비 부담이 작고(공개 데이터 확보 완료), 본선 인터넷 여부에 덜 의존
- A보다: AI 에이전트 필연성이 구조적으로 높음
- E보다: 예선 기획서에 공개 데이터 실증을 넣을 수 있음

### 추천하지 않는 조건
- **본선에서 LLM API를 쓸 수 없거나 호출량이 크게 제한**되는 경우 (대량 응답 생성이 불가 → 패널 규모 축소 필요, 심하면 성립 불가)
- 본선 "구체화 과제"가 시뮬레이션이 아니라 **서비스 아키텍처 문서화 위주**로 나오는 경우 (구현 강점이 묻힘)

## 3. 2순위 — B. 롯데케미칼: 이벤트 인지형 수요예측 에이전트

### 선정 이유
- LLM 역할(비정형 뉴스 → 구조화 이벤트)이 분명하고, **보정 전후 오차로 LLM 기여를 정량 증명**하는 설계가 가장 엄밀
- 본선 현장 데이터가 실제 수요 데이터일 가능성이 높아 [가설] 대리 타깃 문제가 해소됨
- 사용자 배경(예측 모델링 + LLM)이 가장 직접적으로 드러남

### 가장 중요한 차별화 요소
LLM이 숫자를 예측하지 않고 **사실만 추출**, 영향 크기는 통계 모델이 학습 → 환각·사전지식 누출을 통제한 "검증 가능한 LLM 활용"

### 개발 난이도: **중상**
### 필요한 기술 스택
pandas, LightGBM/statsmodels, (선택) 사전학습 시계열 모델, OpenAI 구조화 출력, GDELT, 관세청 무역통계, Streamlit

### 최소 개발 범위
ABS·PC × 주요 수출국 3~5개, 2017~2024 월간, 이벤트 유형 6종, 보정 전후 백테스트, 원인 조사는 과거 사례 2~3건

### 예상되는 최대 위험 요소
- **보정 효과가 통계적으로 유의하지 않게 나올 위험** (짧은 월간 데이터, 드문 이벤트)
- 본선 인터넷 불가 시 뉴스 수집 불가 → 현장 데이터 기간에 맞는 뉴스를 미리 갖출 수 없음

### 다른 후보보다 유리한 점
- 공식 과제 문구("AI 기반 정밀 수요예측 프레임워크")와 기술적으로 가장 정면 대응
- 정량 검증 체계가 가장 탄탄함 → 심사 기준 "결과 정확성 및 성능"에 직접 대응

### 추천하지 않는 조건
- 주 10시간 미만으로 준비 시간이 부족한 경우 (뉴스·라벨링 준비가 무거움)
- 본선 인터넷 사용 불가가 확정되는 경우

## 4. 3순위 — A. 롯데웰푸드: 가설 검증형 수출 시장 분석 에이전트

### 선정 이유
- 공개 데이터로 예선 실증이 가장 쉽고 안정적
- 공식 과제(성장성·트렌드·수출입 통계 → TOP 3 + 근거)와 거의 완전히 일치

### 가장 중요한 차별화 요소
"가중 점수표"가 아니라 **담당자의 가설을 에이전트가 과거 데이터로 검증**하고, 통과한 근거만 TOP 3 판단에 사용

### 개발 난이도: **중** (단순 순위 모델이면 하, 가설 검증 에이전트로 재설계하면 중상)
### 필요한 기술 스택
pandas, statsmodels(PPML 중력모형), LightGBM 순위 학습, UN Comtrade·CEPII·World Bank, OpenAI 함수 호출 + 코드 실행 샌드박스, Streamlit

### 최소 개발 범위
품목 2개(비스킷류·빙과), 국가 약 100개, 백테스트 시점 3개, 가설 템플릿 5종 검증, TOP 3 리포트

### 예상되는 최대 위험 요소
- **에이전트 필연성 공격** ("엑셀 점수표 + 분석가로 충분")
- 재설계 시 LLM이 만든 분석 코드 오류, 다중 검정 문제

### 다른 후보보다 유리한 점
- 데이터 확보 위험이 가장 낮고, LLM API 제약에도 핵심 기능이 일부 작동

### 추천하지 않는 조건
- 심사에서 "AI 에이전트 완성도"의 비중이 크다고 판단될 때 (배점 비공개라 판단 불가)

## 6. 1순위 기준 다음 단계 제안 (예선 마감 11/4까지, 약 10시간 가정)

| 순서 | 작업 | 예상 시간 |

| 1 | KREI 2025 원자료 로드, A15·A19 문항 세그먼트별 분포 산출 | 1.5h |
